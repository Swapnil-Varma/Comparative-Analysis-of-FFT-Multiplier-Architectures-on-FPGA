# Modified Booth FFT — MATLAB Integration

## 1. Overview

This folder provides MATLAB integration for the **8-point Radix-2 DIT FFT using a Modified Booth multiplier**.

Purpose: compare the FFT output generated by the Vivado/Verilog simulation with the corresponding MATLAB FFT using the same input samples.

### Project configuration

- 8-point FFT
- Radix-2 Decimation-in-Time (DIT)
- 16-bit signed fixed-point arithmetic
- Q1.15 representation
- Modified Booth multiplier
- Xilinx Vivado / XSim for Verilog simulation
- MATLAB for numerical verification only

The reference paper describes the Modified Booth FFT as a signed, two's-complement, Radix-4 Booth architecture intended to reduce partial products and provide an area-oriented implementation.

## 5. Q1.15 Fixed-Point Format

The FFT uses signed 16-bit Q1.15 values.

```text
16 bits
[ Sign ][----------- 15 Fraction bits -----------]
```

Conversion from a signed integer to decimal:

```matlab
value = fixed_value / 32768;
```

Examples:

```text
16384  ->  +0.5
-16384 ->  -0.5
```

A 16-bit × 16-bit multiplication produces a 32-bit product. For Q1.15 operands, the raw product has approximately Q2.30 scaling and must be shifted/scaled back appropriately by the Verilog design.

---

## 6. Modified Booth Multiplier

The Modified Booth multiplier uses signed two's-complement arithmetic.

Conceptually:

```text
16-bit × 16-bit
       |
       v
Modified Booth encoding
       |
       v
Reduced partial products
       |
       v
Partial-product accumulation
       |
       v
32-bit product
```

The MATLAB script must compare the **final FFT output**, not the internal partial products.

---

## 7. FFT Scaling

Check the actual Verilog RTL before applying a correction factor.

If the butterfly performs divide-by-2 scaling at all three stages:

```text
Stage 1 -> /2
Stage 2 -> /2
Stage 3 -> /2
```

then the total FFT scaling is:

```text
1/2 × 1/2 × 1/2 = 1/8
```

and MATLAB comparison should use:

```matlab
X_hw_corrected = X_hw * 8;
```

Do **not** use a scale factor of 8 unless the actual Verilog implementation performs these three divide-by-2 operations.

## 8. MATLAB Script

Create:

```text
booth_fft_matlab.m
```

in the same directory as `booth_fft_output.csv`.

Use:

```matlab
clc;
clear;
close all;

%% ============================================================
% MODIFIED BOOTH FFT - MATLAB VERIFICATION
% 8-Point Radix-2 DIT FFT
% 16-bit Q1.15 Fixed Point
% ============================================================

%% Input signal
% IMPORTANT: This must exactly match the Verilog testbench input.

input_signal = [
     0.100006
     0.200012
    -0.100006
     0.149994
    -0.200012
     0.049988
     0.250000
    -0.100006
];

%% MATLAB reference FFT
X_matlab = fft(input_signal);

%% Read Vivado CSV
filename = 'booth_fft_output.csv';

data = readmatrix(filename);

%% Extract CSV columns
bin     = data(:,1);
real_hw = data(:,2);
imag_hw = data(:,3);

%% Convert raw Q1.15 integers to decimal
% Use these lines ONLY if the CSV stores raw signed 16-bit integers.

real_hw = real_hw / 32768;
imag_hw = imag_hw / 32768;

X_hw = real_hw + 1j*imag_hw;

%% Hardware scaling
% If the Verilog FFT divides each of its 3 stages by 2:
%
% X_hw_corrected = X_hw * 8;
%
% Otherwise use the actual scaling implemented by the RTL.

X_hw_corrected = X_hw;

%% Display comparison
fprintf('\n');
fprintf('============================================================\n');
fprintf('          MODIFIED BOOTH FFT COMPARISON\n');
fprintf('============================================================\n');

fprintf('%5s %18s %18s %18s %18s\n', ...
    'Bin', 'MATLAB Real', 'HW Real', 'MATLAB Imag', 'HW Imag');

fprintf('------------------------------------------------------------\n');

for k = 1:8
    fprintf('%5d %18.8f %18.8f %18.8f %18.8f\n', ...
        bin(k)-1, ...
        real(X_matlab(k)), ...
        real(X_hw_corrected(k)), ...
        imag(X_matlab(k)), ...
        imag(X_hw_corrected(k)));
end

fprintf('============================================================\n');

%% Error calculation
error_complex = X_matlab - X_hw_corrected;

absolute_error = abs(error_complex);

max_error  = max(absolute_error);
mean_error = mean(absolute_error);
rmse       = sqrt(mean(absolute_error.^2));

fprintf('\n');
fprintf('Maximum Absolute Error : %.10f\n', max_error);
fprintf('Mean Absolute Error    : %.10f\n', mean_error);
fprintf('RMSE                   : %.10f\n', rmse);

%% Pass / Check
tolerance = 0.01;

if max_error <= tolerance
    fprintf('\nRESULT: PASS\n');
    fprintf('Hardware FFT output is within the selected tolerance.\n');
else
    fprintf('\nRESULT: CHECK\n');
    fprintf('Hardware FFT output exceeds the selected tolerance.\n');
end

%% Magnitude comparison
figure;
stem(0:7, abs(X_matlab), 'filled');
hold on;
stem(0:7, abs(X_hw_corrected));
grid on;
xlabel('FFT Bin');
ylabel('Magnitude');
title('Modified Booth FFT - MATLAB vs Hardware');
legend('MATLAB FFT', 'Vivado FFT');

%% Absolute error
figure;
stem(0:7, absolute_error, 'filled');
grid on;
xlabel('FFT Bin');
ylabel('Absolute Error');
title('Modified Booth FFT - Absolute Error');
```

## 9. If the CSV Already Contains Decimal Values

If the CSV contains values such as:

```text
0.1234
-0.5678
```

rather than raw Q1.15 integers, do **not** divide by 32768.

Remove/comment:

```matlab
real_hw = real_hw / 32768;
imag_hw = imag_hw / 32768;
```

Use:

```matlab
X_hw = real_hw + 1j*imag_hw;
```

The MATLAB conversion must match the actual CSV format generated by the Verilog testbench.

## 11. What MATLAB Does

The script:

1. Defines the same 8 input samples used by Verilog.
2. Calculates the reference FFT using `fft()`.
3. Reads the Vivado CSV.
4. Converts raw Q1.15 values if necessary.
5. Applies the required hardware scaling if necessary.
6. Compares real and imaginary outputs.
7. Calculates maximum absolute error.
8. Calculates mean absolute error.
9. Calculates RMSE.
10. Reports PASS/CHECK.
11. Plots magnitude comparison.
12. Plots absolute error.

## 12. Troubleshooting

### File not found

If MATLAB reports:

```text
Error using readmatrix
File 'booth_fft_output.csv' not found.
```

run:

```matlab
pwd
dir
```

and verify that `booth_fft_output.csv` is in the current folder.

### Wrong number of rows

An 8-point FFT should produce bins:

```text
0 1 2 3 4 5 6 7
```

If not, check the CSV-writing section of the Verilog testbench.

### Large error

Check these in order:

1. Input vector exactly matches Verilog.
2. Q1.15 conversion is correct.
3. CSV is not being divided by 32768 twice.
4. FFT scaling matches the RTL.
5. Twiddle factors are correct.
6. Signed two's-complement arithmetic is used.
7. Complex multiplication is:
   - Real = `ac - bd`
   - Imag = `ad + bc`
8. Output bin ordering is correct.

## 13. Vivado and XDC

MATLAB integration does not change the FPGA architecture or XDC.

Changing the testbench or adding CSV output normally does not require an XDC change.

Use the same XDC as the other FFT architectures when the top-level FPGA ports, clock and timing requirements are identical.

Only change the XDC if the actual FPGA top-level interface or timing constraints change.
